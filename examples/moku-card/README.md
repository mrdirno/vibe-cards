# Mokume Photonic Lattice — MOKU-003

Card 003 of [Compound Craft, Book One](../../src/site/compound-craft/index.html).
Page: <https://mrdirno.github.io/vibe-cards/moku/>

```
package/index.html   the card, as it arrived and then as it was fixed
designs/             the print artifacts, written by tools/intake_card.py
assets/qr_moku.png   the QR, generated by tools/make_qr.swift
docs/                the generator's own paperwork, kept verbatim
tools/               the generator's four python scripts, unmodified
```

## Where it came from

It was generated somewhere else and handed over as a folder. It did not come
from this repository and it is not a fork of anything in it. `docs/` is that
folder's own paperwork — a README, a design blueprint, an evals file, an
authorship disclosure, a list of what its build killed, and a freeze manifest of
SHA-256 hashes.

**Those hashes describe the package as it ARRIVED, not as it ships.** Four
things had to change before it could be a card here, and `index.html` no longer
matches its recorded hash. That is not a corruption; it is the record of an
intake. The list is below so the difference is legible rather than mysterious.

`docs/wish-it-better.json` is kept for the same reason and is **not live
configuration**. It names a `mailto:` address and a Supabase project that are
not this project's. The card's actual wishing well is the one every other page
here uses, and it is wired in `package/index.html`.

## What had to change, and why

**1. The address it pointed at did not exist.** The QR and the `#vc-card` block
both carried `https://compound-crafts.io/cards/MOKU-003`. That domain does not
resolve — `dig +short compound-crafts.io` returns nothing and a request to it
gets no response at all. So the finished card would have scanned cleanly and
gone nowhere, which is the failure this repository has hit before and has a
commit named after it. Every occurrence now reads
`https://mrdirno.github.io/vibe-cards/moku/`, and a page exists there.

The package's own `docs/EULOGY.md` lists "Placeholder QR" as a defect it killed,
and records the payload as verified. It was not. A generator cannot check that a
domain it invented resolves.

**2. The QR could not be aimed, and one of the two was not a QR.** The image was
assigned by a script at runtime out of a `<script type="text/plain">` holder,
with a hard-coded fallback that the code's own comment admitted does not decode
— 133 bytes, and `tools/qrdecode` reports NO BARCODE DETECTED on it. A face that
needs JavaScript to draw its own QR prints blank when the script does not run,
and a fallback that does not decode is worse than no fallback.

The QR now sits directly on the `<img>` as a data URI, marked `data-vc-qr` so
`tools/intake_card.py` knows which image to burn rather than guessing. The
runtime injection and the dead fallback are gone.

**3. Three things were printing on the card that should not have been.** They
were found by `tools/measure_faces.mjs`, which this card is the reason for:

- a label reading `Face 1 — Editorial / Forge` in the top-left corner of the
  front, and its twin on the back — preview annotations left in the artwork;
- the dashed safe-zone rectangle, a proofing guide, drawn inside the face, so
  the guide would have printed along with the card;
- the address caption, set vertically at 3.8 pt and sitting 1.08 mm off the
  bottom edge. The safe zone is 3.95 mm, so a trim anywhere in tolerance clips
  it. The typable address moved to the back, horizontal, inside the safe zone.

**4. The wishing well posted to a project that is not this one**, with a key
whose own value ends `fake_anon_key_for_offline_demo`. It now uses the endpoint
and public key in `src/site/_wish/config.json`, like every other page here.

## Rebuilding the print artifacts

```bash
python3 tools/intake_card.py examples/moku-card/package --slug moku \
        --name "Mokume Photonic Lattice" --asset-prefix moku
node tools/measure_faces.mjs examples/moku-card/package/index.html
```

The first writes `designs/`, the Card Studio copies under `src/web/cards/`, and
the page thumbnails under `src/site/moku/`. It generates the QR itself from the
slug, so the address on the card cannot drift from the address of the page. The
second reports every text box in millimetres and exits non-zero if anything sits
inside the trim margin.

Note that this card puts its QR on the **front**. Cards 001 and 002 put theirs
on the back, and `intake_card.py` used to verify the back only — so it printed
`qr_matches_url: false` next to `ok: true` and exited 0. It reads both faces
now, and refuses when neither carries the card's own URL.

## What this card leaves behind

`tools/measure_faces.mjs`. Every gate here checked the card as a file — is the
PNG 2066×1319, does the QR decode, is the PDF placement right. None of them
looked at where the type sits, which is where an incoming package actually
breaks: all three defects in item 3 above passed every existing check. It takes
any package's `index.html` and works on cards authored in millimetres or on the
600 dpi pixel grid, because it derives the scale from the face's own box.
